About RAGnosis

A graph before the answer.

RAGnosis is a biomedical conversational interface built around retrieval from a Neo4j knowledge graph followed by language generation through Cohere Chat.

The idea

A chat that looks up the graph before it speaks.

You describe symptoms in the browser. Flask posts that turn, plus the on-page transcript, to POST /chat. The server searches Neo4j Aura, then asks Cohere to reply using the retrieved properties and the conversation so far.

The live production path is keyword retrieval, not vector search. Matching uses Cypher CONTAINS over name, text, description, disease, symptom, title, and canonical_name, limited to five nodes. Embedding fields are stripped before context is sent to the model.

Query path

How a turn moves through the system

01 · Browser

index.html keeps the transcript as patient/doctor turns. There is no durable server-side conversation store.

02 · Flask

app.py serves the UI, exposes GET /health, and runs retrieval plus generation on POST /chat.

03 · Neo4j Aura

A remote graph, connected lazily over neo4j+s. The web process does not run Neo4j itself.

04 · Cohere Chat

Primary model command-a-03-2025, with fallback command-r7b-12-2024 if the primary model is unavailable.

Production

What is deployed

The Render web service is Flask, remote Neo4j Aura, Cohere Chat, and this HTML UI. gunicorn binds 0.0.0.0 and the host-provided PORT.

GET /health reports process liveness even when Aura or Cohere is down. /chat returns the real retrieval or generation error instead of a fabricated answer.

This deployment is text chat only. Voice input, speech synthesis, Gradio, image upload, and notebook-only RAG variants are not part of the production path.

Experiments

What stays off the live path

Notebooks, Colab pipeline exports, and milestone diagrams live under experiments/. CLI and similarity ingestion live under scripts/. Those files document how the graph and earlier RAG prototypes were built. They are not served by gunicorn.

Offline CSVs and a graph dump sit in Database/. They are research and ingestion inputs. gunicorn does not load them at startup, and they do not define the live Aura graph.

Retrieval

Each message is searched in Neo4j Aura with case-insensitive CONTAINS on selected properties. At most five nodes come back. Those properties, without embedding vectors, are passed to Cohere with the current transcript.
